# 范围与路线图

## 产品定义

一个面向个人设备管理和 IT 技术支持的远程控制产品。一个 Android 应用同时具备主控和被控能力；Windows 客户端同时具备主控、被控和后台服务能力。

“完整控制 Android”指被控端用户完成录屏和输入控制授权后，远端可以看屏、点击、滑动、输入文字及执行返回/Home/任务等操作。它不表示可以绕过 Android 系统授权，也不承诺所有品牌手机都能永久静默无人值守。

## 阶段 0：质量 POC（4 周目标）

### 第 1 周：可重复构建与基线

- 固定上游版本和子模块提交。
- 在本地和 CI 构建 Windows x64 与 Android arm64 调试包。
- 验证四个控制方向的连接、画面和输入基线。
- 记录上游原版的 CPU、GPU、码率、FPS、延迟和直连率。

### 第 2 周：全链路可观测

- 为捕获、编码、排队、发送、接收、解码和呈现加入单调时间戳。
- 增加仅在质量测试开关开启时显示的会话 HUD。
- 支持导出不含画面内容和输入内容的 JSON 指标。
- 建立 720p30、1080p30 和 1080p60 可重复基准。

### 第 3 周：热路径优化

- Windows 优先验证 DXGI 捕获、GPU 纹理和硬件编码的少拷贝路径。
- Android 优先验证 MediaProjection Surface 到 MediaCodec 的硬编路径。
- H.264 硬编硬解作为默认基线，H.265 只在双端能力匹配时启用。
- 控制事件高优先级；鼠标移动合并旧事件，点击和键盘事件可靠有序。

### 第 4 周：弱网与设备矩阵

- 执行局域网、同区域公网和跨境测试。
- 验证限带宽、延迟、抖动和丢包下的动态降级。
- 覆盖至少两种 Windows GPU 和三个 Android 厂商。
- 根据《质量验收标准》作出继续优化或进入 Alpha 的决定。

## 后续阶段

| 阶段 | 目标 | 入口条件 | 预计周期 |
|---|---|---|---:|
| Alpha | 小规模真实会话，完成一次性协助码、设备列表和基本风控 | POC 达标 | 6–10 周 |
| 封闭 Beta | 100–500 用户，中国与海外节点，自动更新与崩溃监控 | Alpha 连续稳定 | 8–16 周 |
| 付费 V1 | 个人套餐与 IT 支持座席，计费、审计、客服和合规上线 | Beta 指标和安全审计通过 | 8–16 周 |

## POC 明确不做

- 付费、套餐、发票和营销页。
- 4K/8K、144/240/360FPS、HDR、游戏手柄和数位板。
- iOS、macOS 和 Linux 客户端产品化。
- 大规模企业 RBAC、SSO、屏幕墙和云录像。
- 绕过 Android 的录屏或无障碍授权。
